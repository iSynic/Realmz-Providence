# Get started with Providence

Start with a small route that you can explain and test. A useful first slice is
a starting square, a short path, one visible event and a clear destination.

1. Use **File → New Project** for new work, or open an existing portable project.
   To bring in Classic content, import it into a suitable project; see
   [Scenario Setup](scenario-setup.md).
2. In [Scenario](scenario-shell.md), set the intended starting map and coordinate.
3. Open [Maps](maps.md), create or select the level, and author the route's terrain.
4. Add an [Action Point](action-points.md) or [encounter](encounters.md) that
   displays a [String](text-and-messages.md). Use the actual saved target number.
5. Apply the edited forms, then Save. Follow callers and **View Flow** to inspect
   the applied connections. A reference alone does not prove physical access.
6. Open **Validate**, review the actionable findings and then check the desired
   [Publish target](validate-and-publish.md). Export to a new destination.
7. Use a compatible separate Rebuilt installation to exercise the route. Check
   choices, costs, return visits and Save/reload around consequential events.

The left activity navigation selects an authoring area; its route list selects
the workbench. The centre contains the active document. Contextual inspectors,
palettes and caller views support that document. Menu commands can depend on
the selected record, focused control, open project or current operation.

Keep edits in the owning workbench. Apply commits a draft to project history;
Save writes the project. A navigation guard asks how to handle unapplied work.
If an operation's result is uncertain, use its status/recovery action or reopen
before trying the mutation again. Do not infer failure merely from a lost reply.

Keep the original Classic scenario unchanged while editing the imported project.
Do not overwrite an original folder with a test export.
