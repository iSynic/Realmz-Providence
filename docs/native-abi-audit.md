# Realmz Native ABI Audit

## Scope

This audit covers every Providence-writable fixed-record layout that is backed by a native Realmz C struct. It verifies:

- the native record size;
- every top-level member offset and byte width;
- every interior padding range;
- the browser and Rust offsets at padding and mixed-width boundaries;
- the record-size policy shared by browser and Rust compilers;
- classification of every writable container in the scenario byte-ownership inventory.

It does not reopen established field meanings or runtime semantics. Uniform arrays, fixed-text rows, and sequential file formats are classified and included in the writable-container coverage count, but they do not have C `offsetof` values to probe.

The stop condition is: every writable container is classified, every struct-backed container has compiled size/member evidence, every native padding byte is enumerated, and every padding or mixed-width boundary consumed by Providence has a browser/Rust conformance check.

## Authority

The committed report is generated by compiling
[`scripts/realmz_native_abi_probe.c`](../scripts/realmz_native_abi_probe.c) against Realmz's actual declarations:

- Realmz commit `0c19b9159ae1d982147f4dc5a3fd465b65a4e244`
- `src/realmz_orig/structs.h` SHA-256 `451FC83F7B3FCD17E39EBBCF9981B8041F6D5F75F1A219ECE061676F142C146E`
- `src/Types.h` SHA-256 `5F0D9B1F0B737439621140AC3E0F001C6F24BF0D6D73D2FBC17E2E4C6C87E99F`

The probe is compiled once with the compiler's normal layout and once with an explicit two-byte maximum struct packing mode. All 18 layouts and 290 member rows are identical between those modes, so none of the audited results depends on a host compiler choosing four-byte rather than two-byte aggregate alignment.

The machine-readable result is
[`docs/generated/realmz-native-abi-audit.json`](generated/realmz-native-abi-audit.json).

## Result

No additional native-layout discrepancy was found.

The gate binds the probe to 65 browser/Rust padding and mixed-width consumer assertions. Eight executable sentinel tests cover each of the four native padding boundaries in both implementations with distinct adjacent bytes, including the one-byte splice pattern that exposed `randlevel`.

| Native struct | Providence container(s) | Native bytes | Composite bytes | Interior padding |
| --- | --- | ---: | ---: | --- |
| `restrictinfo` | `Data RI` | 320 | 320 | none |
| `contactdata` | `Data CI` | 4608 | 4608 | none |
| `door` | `Data DD`, `Data DDD` | 40 | 40 | none |
| `race` | `Data Race` | 408 | 408 | none |
| `mapstats` | `Data Custom 1/2/3 BD` table | 40 | 40 | none |
| `caste` | `Data Caste` | 576 | 576 | none |
| `battle` | `Data BD` | 346 | 346 | byte 339 |
| `timeencounter` | `Data TD3` | 40 | 40 | none |
| `monster` | `Data MD`, `Data MD1`, `Data MD-1` | 210 | 210 | none |
| `maps` | `Data MD2` | 340 | 340 | none |
| `thief` | `Data TD2` | 118 | 118 | none |
| `randlevel` | `Data RD`, `Data RDD` | 644 | 644 | byte 563 |
| `treasure` | `Data TD` | 48 | 48 | none |
| `encount2` | `Data ED2` | 160 | 520 with nine 40-byte text slots | byte 157 |

| `shop` | `Data SD` | 3002 | 3002 | none |

The four padding bytes are handled as native padding, not semantic data:

- `battle[339]` separates `dist` from `messagebefore`;
- `encount[103]` separates `castesuccess` from `prompt`;
- `encount2[157]` separates `thieffail` from `prompt`;
- `randlevel[563]` separates `option[20]` from `sound[20]`.

Fresh or authored semantic records canonicalize those bytes to zero. Untouched imported records remain byte-identical through the compatibility annex/raw-source preservation path; `randlevel[563]` is also copied explicitly when an imported random-level record is partially recompiled.

The other 13 writable containers are non-struct layouts: uniform short/byte tables, fixed-text records, or sequential file formats. The generated report classifies each one so a newly writable or newly discovered container makes the audit gate fail until it is assigned either a native struct or an explicit non-struct classification.

## Reproduction

Generate the authoritative report from a Realmz checkout:

```powershell
npm run audit:realmz-native-abi -- --realmz-root "F:\Realmz"
```

Check the committed report, policy sizes, writable-container inventory, and browser/Rust boundary consumers without requiring the Realmz checkout:

```powershell
npm run check:realmz-native-abi
```

Compare the committed report with a fresh authoritative probe without rewriting it:

```powershell
node scripts/audit_realmz_native_abi.mjs --check --realmz-root "F:\Realmz"
```

`check:realmz-native-abi` is part of `check:native-compiler-convergence`, so normal compiler and release verification cannot silently drop this coverage.
